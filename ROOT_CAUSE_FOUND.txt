====================================================================================================
 THE ROOT CAUSE
====================================================================================================

In app/cloud_api_researcher.py (lines 393-400), the researcher was REMAPPING field names:

BEFORE (BROKEN):
```python
all_endpoints.append({
    "vendor_operation": ep.get("operation_name", ""),  # Renamed!
    "endpoint": ep.get("path", ""),  # Renamed!
    "method": ep.get("method", ""),
    ...
})
```

But in app/endpoint_validator.py (line 77), the validator expects ORIGINAL field names:

```python
def validate_endpoint(self, endpoint: Dict):
    path = endpoint.get('path', '')  # Looks for "path", not "endpoint"!
    method = endpoint.get('method', '')
    ...
```

WHAT HAPPENED:
1. OpenAPI parser creates: {"path": "/users.list", "operation_name": "users.list", ...}
2. Researcher remaps to: {"endpoint": "/users.list", "vendor_operation": "users.list", ...}
3. Validator looks for: endpoint.get('path', '')
4. Gets empty string: ''
5. Validation fails: "Invalid path structure"

====================================================================================================
 THE FIX
====================================================================================================

AFTER (FIXED):
```python
endpoint_data = {
    "method": ep.get("method", ""),
    "path": ep.get("path", ep.get("endpoint", "")),  # Keep "path" as "path"
    "operation_name": ep.get("operation_name", ep.get("vendor_operation", "")),  # Keep original
    "description": ep.get("description", ""),
    "source_url": page.get("url", ""),
    "category": ep.get("category", "other"),
    # Legacy fields for backward compatibility
    "vendor_operation": ep.get("operation_name", ep.get("vendor_operation", "")),
    "endpoint": ep.get("path", ep.get("endpoint", ""))
}
```

KEY CHANGES:
1. DON'T remap field names
2. Keep "path" as "path" (validator expects this)
3. Keep "operation_name" as "operation_name"
4. ADD legacy field names for backward compatibility
5. Support BOTH naming conventions (OpenAPI + HTML scraper)
