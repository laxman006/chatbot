====================================================================================================
 LLM-POWERED EXTRACTION FALLBACK - SOLUTION FOR JAVASCRIPT-RENDERED DOCS
====================================================================================================

PROBLEM IDENTIFIED:
- Canny's API documentation (https://developers.canny.io/api-reference) is JavaScript-rendered
- BeautifulSoup only sees empty HTML shell, not the content loaded by JavaScript
- Result: 0 endpoints extracted despite correct URL discovery
- Enhanced HTML parsing strategies don't help with JS-rendered content

====================================================================================================
 ROOT CAUSE
====================================================================================================

Modern API documentation sites use JavaScript frameworks (React, Vue, Angular) to render content:

1. Server sends minimal HTML shell
2. JavaScript framework loads in browser
3. JavaScript fetches data and renders content
4. BeautifulSoup CANNOT execute JavaScript

**Example:**
```html
<!-- What BeautifulSoup sees: -->
<div id="app"></div>
<script src="main.js"></script>

<!-- What browsers see after JS runs: -->
<div id="app">
  <h2>List users</h2>
  <code>POST /api/v2/users/list</code>
  <p>Returns a list of users...</p>
</div>
```

BeautifulSoup sees the FIRST version (empty div), not the second (rendered content).

====================================================================================================
 SOLUTION: 3-TIER EXTRACTION STRATEGY
====================================================================================================

The system now uses a **3-tier fallback strategy**:

## TIER 1: OpenAPI/Swagger Spec Parsing (PRIMARY)
- Look for OpenAPI/Swagger JSON specs
- Works for ~40% of modern APIs
- Most reliable when available

## TIER 2: HTML Scraping (FALLBACK 1)
- 7 extraction strategies for different HTML patterns
- Works for ~50% of APIs with standard HTML docs
- Fast and doesn't require LLM

## TIER 3: LLM-Powered Extraction (FALLBACK 2 - NEW!)
- **Activates when Tier 1 + Tier 2 return 0 endpoints**
- Uses LLM's knowledge of the cloud's API
- Extracts the 8 essential CloudFuze Manage operations
- Works for JavaScript-rendered docs

====================================================================================================
 HOW LLM EXTRACTION WORKS
====================================================================================================

When HTML scraping returns 0 endpoints:

1. **Detect the issue:**
   ```
   total_endpoints = 0
   → Likely JavaScript-rendered
   ```

2. **Prepare context:**
   - Documentation URL
   - Any scraped text content (even if no endpoints)
   - Cloud name

3. **Prompt LLM:**
   ```
   "You are an expert at analyzing API documentation.
   The HTML scraping failed for {cloud_name}.
   
   Extract the 8 essential operations:
   1. getUsers
   2. getAdmins
   3. createUser
   4. deleteUser
   5. getGroups
   6. getGroupMembers
   7. addUserToGroup
   8. removeUserFromGroup
   
   Based on your knowledge of {cloud_name}'s actual API..."
   ```

4. **Parse LLM response:**
   - Extracts JSON array of endpoints
   - Each endpoint has: method, path, description, operation_name

5. **Return endpoints:**
   - Fed into normal normalization pipeline
   - Validated and mapped like any other endpoints

 KEY ADVANTAGES

3. **Focused on essentials** - Only extracts 8 core CloudFuze Manage operations

====================================================================================================
 LIMITATIONS & ACCURACY
====================================================================================================

## Strengths:
- ✅ Works for popular/well-known clouds (Canny, Notion, Linear, etc.)
- ✅ LLM has been trained on their public documentation
- ✅ Focused extraction (8 operations) is more accurate than broad extraction
- ✅ No additional dependencies needed

## Limitations:
- ⚠️ May not work for very obscure/new clouds
- ⚠️ LLM's training data may be outdated for recent API changes
- ⚠️ Still requires validation against actual endpoints
- ⚠️ Uses LLM tokens (cost consideration for high volume)

## Mitigation:
- Validation layer still checks semantic correctness
- Confidence scoring accounts for extraction method
- Documentation links provided for manual verification
