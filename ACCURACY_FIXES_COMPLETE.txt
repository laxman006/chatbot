 ISSUES FIXED
====================================================================================================

🔴 ISSUE 1: Missing Operations (createUser, deleteUser, updateUser, etc.)
----------------------------
ROOT CAUSE: Basic regex scraper couldn't extract endpoints from structured HTML (tables, divs)

✅ FIX: Complete scraper rewrite with 4 extraction strategies:
   1. HTML Table Extraction - Parses API reference tables (method, endpoint, description columns)
   2. Structured HTML Extraction - Finds endpoints in divs/sections with semantic classes
   3. Code Block Extraction - Enhanced pattern matching in <code> and <pre> tags
   4. Regex Fallback - Improved regex patterns as last resort

RESULT: Now extracts from Okta's structured documentation tables correctly.

----------------------------

🔴 ISSUE 2: Method: UNKNOWN
----------------------------
ROOT CAUSE: Scraper only finding paths without HTTP methods

✅ FIX: Multi-pronged HTTP method detection:
   1. Table column extraction (Method/Verb/HTTP column)
   2. Semantic HTML class/span detection (method badges)
   3. Contextual search - finds method near endpoint path in text
   4. Pattern matching improvements

RESULT: Proper method extraction (GET, POST, PUT, DELETE, PATCH).

----------------------------

🔴 ISSUE 3: Wrong Endpoints (suspend endpoint was for apps, not users)
----------------------------
ROOT CAUSE: No semantic understanding of endpoint purpose

✅ FIX: Operation name inference:
   - Extracts description from documentation
   - Infers operation from path patterns + method
   - Example: POST /users/{id}/lifecycle/suspend → "suspendUser"
   
RESULT: Correct endpoint-to-operation mapping.

----------------------------

🔴 ISSUE 4: Wrong SCIM Detection ("SCIM None")
----------------------------
ROOT CAUSE: Only checking content text, not actual endpoints or URLs

✅ FIX: 3-tier SCIM detection:
   1. Check for /scim/ paths in extracted endpoints
   2. Check content for SCIM mentions with version detection
   3. Check documentation URLs for SCIM links
   4. Default to 2.0 if SCIM found but version unclear

RESULT: Accurate SCIM detection with correct version (2.0, 1.1, or None).

----------------------------

🔴 ISSUE 5: Inflated Confidence (0.92 with 33% coverage)
----------------------------
ROOT CAUSE: Confidence based on pages scraped, not actual accuracy

✅ FIX: Completely redesigned confidence scoring:
   - 50% weight: Core operation coverage (mapped ops / 11 expected)
   - 30% weight: HTTP method completeness (penalizes UNKNOWN methods)
   - 20% weight: Average normalization confidence
   
NEW FORMULA:
   - 0.9-1.0: Excellent (most ops mapped with known methods)
   - 0.7-0.9: Good (core coverage, minor gaps)
   - 0.5-0.7: Fair (basic coverage, significant gaps)
   - 0.0-0.5: Poor (missing many ops or unknown methods)

RESULT: With 6/11 core ops and some UNKNOWN methods → ~0.55-0.65 (Fair), NOT 0.92.

----------------------------

🔴 ISSUE 6: Missing Group Operations
----------------------------
ROOT CAUSE: Endpoints not being extracted + LLM prompt too weak

✅ FIX: 
   1. Better extraction (see Issue 1)
   2. Improved LLM normalization prompt with:
      - Explicit mapping examples
      - Pattern matching rules
      - Clear instructions to match method + path first

RESULT: Group operations (getGroupMembers, addUserToGroup, etc.) now properly detected.

🔴 ISSUE 7: Logical Inconsistency (33% coverage = "Good")

✅ FIX: Updated research notes to reflect actual quality:
